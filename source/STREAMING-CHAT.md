# 流式回复与随时接话（共同源码 v1.40）

GPT 与 DeepSeek 共用这一套交互，原来的角色设定、上下文、长期记忆和本地语音模型保持兼容。

## 使用

- 发消息后，模型返回的中文逐段出现在同一个气泡里，不必等待整段结束。
- 启用日语配音时，完整日语句子到达后就加入现有配音队列；按顺序合成播放，最后不会再把整段重读一次。实际出声仍需要等待本地音色服务完成合成。
- 杏菜正在生成或说话时，按住鼠标后退侧键即可停止当前生成与配音并开始录音，松开后识别并发送。点击聊天窗口的「停止」也可打断，然后重新输入。
- 已显示的中断回复会标记为「未完成」并保存，下一轮可以接着聊；没输出任何内容的中断请求也有明确记录。
- 输入框有未发送草稿时，侧键不会覆盖它。空录音或上一段录音迟到的结果不会打断后来发出的新消息。
- 打断不能撤销已经发给 QQ 音乐的操作。真实回执保存在原来那一轮，未确认开始播放时会明确说明。

## 实现边界

使用现有 OpenAI Responses / DeepSeek Chat Completions SSE。普通聊天及音乐执行后的讲解流式输出；点歌意图解析、摘要和记忆提取仍使用完整结构化结果。中文和日语沿用双语 JSON 协议，界面只显示解码后的中文，完整日语句子才进入语音队列。推理内容和 JSON 字段不会展示为回答。

每轮独立取消并校验归属，防止旧网络流、音频生成和 finally 修改新轮。上翻旧记录重建气泡时仍保留当前回复。连接中断或缺少合法结束事件不算成功；音乐讲解失败时保留实际操作回执、停止未播放的分句，且不重做音乐操作。

本次只更新共同源码和本地 GPT/DeepSeek 试用构建；公开发行目录及 GitHub Release 留待正式发布同步。

## 验证（2026-11-09）

- 流式客户端：GPT / DeepSeek 各 34 项，覆盖事件拆包、UTF-8、JSON 转义、完整分句、取消、异常结束与非流式兼容。
- WPF 流式界面：两版各 117 项，覆盖增量气泡、侧键抢占、空识别、迟到结果、部分记录、重建历史、音乐回执及失败停音。
- 语音队列 85 项、语音服务 61 项；测试使用模拟 HTTP 与音频文件，不以此声称真实设备听感已验证。
- 既有普通上下文各 208 项、点歌 GPT 229 / DeepSeek 228 项、存储各 46 项、语义记忆 84 项通过。
- 两版 v1.40 编译、实际 Windows 桌面原生自检通过，包括托盘/快捷键注册和窗口初始化。沙箱最初因不允许注册快捷键返回错误 5，改在真实桌面完成验证。
- DeepSeek 实网使用合成内容进行了普通流、双语流、取消 3 个检查，均通过。本次直接客户端首段中文约 0.8 秒，首句日语到达约 1.6 秒；这些时间不含前置意图解析与本地音色合成，也不代表所有网络环境的速度。GPT 本次完成离线适配与原生自检，未进行实网调用。

运行离线测试：`run-stream-client-tests.ps1`、`run-stream-ui-tests.ps1`、`run-stream-speech-tests.ps1`。可选实网测试为 `run-live-streaming-tests.ps1 -RunLive -Provider DeepSeek`，使用当前账户配置的密钥并产生 API 用量；默认只编译测试工具。
